## Общие для всех 4 событий правила (можно закладывать как общую логику, не per-event)

- Регистрация подтверждена только после оплаты **на реквизиты** — нужно уточнить у организаторов, это банковский перевод или уже сейчас через Kaspi Pay (влияет на T14/T15)
- Возраст должен точно соответствовать дистанции — иначе не допускается к старту, взнос не возвращается
- Три уровня отмены: обычная отмена (за ~1-2 недели) → медицинская отмена по справке (на пару дней позже) → жёсткий cutoff, после которого возвратов нет вообще. Стоит явно завести на `Event`: `cancellationDeadline`, `medicalCancellationDeadline`
- Претензии по результатам — 48 часов после закрытия мероприятия, только от самих участников, с доказательствами
- Дисквалификация — большой список причин (без номера, механическое средство передвижения, допинг помощи, неспортивное поведение и т.д.) — управляется вручную в момент события, не требует отдельной сущности в БД кроме простого флага `Registration.disqualified`
- Лимит участников варьируется по событию (200/200/300/? у Ski Fest) — уже поддержано схемой (Event-level или через сумму пулов Distance)

## Важное для T30 (пул стартовых номеров)

Диапазоны, которые обсуждали раньше («большая 1-100, средняя 101-200...») — это была общая иллюстрация, ни один реальный забег так не устроен. У каждого события — свой набор дистанций с собственными названиями (Skyrunning/Hard Trail/Radon Trail, 14км/8км, 4 дисциплины × 2-3 дистанции, Мужчины/Женщины/Начинающие). Пулы номеров нужно будет заводить per-Distance при создании конкретного события, без единого шаблона на все забеги.
