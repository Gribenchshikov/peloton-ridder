## Найденные проблемы

### F-01 — линтер не проходил — исправлено

**Серьёзность:** низкая, но блокирует CI, если lint обязательный.

В `app/src/components/Countdown.tsx:23` React ESLint запрещал синхронный вызов `setParts(...)` внутри `useEffect`. Два дополнительных предупреждения — неиспользуемые аргументы server action в `app/src/app/[locale]/admin/events/actions.ts:136-137`.

**Исправление:** первый расчёт countdown теперь запланирован через `setTimeout`, поэтому не вызывает синхронный state update в effect. Неиспользуемые параметры административного action также переименованы при следующей правке этого файла.

### F-02 — просроченная бронь никогда не освобождалась — исправлено

**Серьёзность:** высокая перед запуском реальной регистрации.

`createRegistrationAction` записывает `reservedUntil` на 30 минут, но ни один код не очищает и не игнорирует брони с истёкшим сроком. `getActiveRegistration` считает активными все `RESERVED`, а расчёт вместимости также включает все `RESERVED`.

**Последствие:** неоплаченная регистрация навсегда занимает место и не даёт тому же пользователю начать регистрацию заново.

**Исправление:** перед созданием новой регистрации просроченные брони этого события атомарно переводятся в `CANCELLED`; активными считаются только `PAID` и `RESERVED` с будущим `reservedUntil`.

### F-03 — гонка при лимите и выдаче стартового номера — частично исправлено

**Серьёзность:** высокая перед запуском реальных платежей.

Проверка свободных мест в `createRegistrationAction` выполнялась отдельно от создания брони. В `confirmPayment` также нет проверки, что свободный номер найден в заданном диапазоне.

**Исправление вне платёжного контура:** строка `Distance` блокируется в транзакции до подсчёта и создания брони, поэтому места нельзя перепродать двумя параллельными регистрациями.

**Отложено по решению владельца:** выдача и уникальность стартового номера в `confirmPayment` остаётся без изменений до подключения Kaspi Pay. Когда появится платёжный контракт, нужно добавить проверку диапазона, уникальность номера в рамках события и интеграционный тест параллельных webhook.

### F-04 — Kaspi Pay пока не интегрирован

**Серьёзность:** ожидаемая незавершённость, критично для production-оплаты.

`app/src/app/api/kaspi/webhook/route.ts` всегда отвечает `501 not_implemented`. Реализована только локальная симуляция оплаты, которая доступна при `ALLOW_TEST_PAYMENTS=true` и отсутствии ключей мерчанта.

**Что сделать:** после получения контракта Kaspi реализовать проверку подписи, идемпотентную обработку webhook, создание заказа/ссылки и отправку подтверждения оплаты.

### F-05 — часть кнопок главной не ведёт в пользовательский сценарий

**Серьёзность:** средняя для готовности публичного сайта.

На главной странице CTA «присоединиться», CTA серии и CTA волонтёрства — обычные `button` без обработчика или ссылки. Страница серии и сценарий волонтёрства пока отсутствуют.

**Что сделать:** до релиза либо добавить соответствующие маршруты/сценарии, либо убрать/заменить кнопки на честные информационные блоки.

### F-06 — локализован интерфейс, но не данные забегов

**Серьёзность:** продуктовая.

`next-intl` настроен корректно на `ru`, `kk`, `en`, но названия, описания трасс, локации, дисциплины и снаряжение приходят из БД одной строкой. Это соответствует текущему бэклогу, но не полноценному мультиязычному контенту.

**Что сделать:** определить модель переводов (`RaceTranslation`/`EventTranslation` или JSON-поля), затем перенести контент для трёх поддерживаемых языков.

## Состояние инфраструктуры

- PostgreSQL 16 уже запущен Docker Compose на `localhost:5432` (`ridder-postgres-1`).
- Контейнер на `localhost:8080` обслуживает прежний nginx-прототип, а не Next.js-приложение из `app/`.
- Новое приложение успешно запущено отдельно через `npm start` на `localhost:3000` для этой проверки.

## Важное уточнение по языкам

Китайский язык не используется в коде: список локалей — `ru`, `kk`, `en`.
